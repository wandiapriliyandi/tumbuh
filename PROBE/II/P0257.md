# P0257 — Bagaimana Membedakan Kebutuhan Philosophy dari Kebutuhan Organisasi?

## Pertanyaan

Jika functional kernel mulai menyusut menjadi beberapa kondisi dasar, bagaimana TUMBUH membedakan mana yang benar-benar merupakan kebutuhan Philosophy dan mana yang sebenarnya hanya kebutuhan organisasi atau repository?

## Titik Berangkat

P0256 menunjukkan bahwa beberapa fungsi governance dapat dikompresi menjadi functional kernel. Tetapi kompresi ini membuka masalah baru.

Sebuah kebutuhan dapat muncul karena:

- Philosophy membutuhkan kondisi tertentu untuk tetap dapat dikaji;
- organisasi membutuhkan cara kerja tertentu agar dapat beroperasi;
- repository membutuhkan cara penyimpanan tertentu agar informasi dapat ditelusuri.

Ketiganya berhubungan, tetapi tidak identik.

## Tiga Level Kebutuhan

Kita dapat membedakan sementara:

### 1. Philosophical Necessity

Kondisi yang diperlukan agar inquiry filosofis tetap masuk akal atau dapat dikoreksi.

### 2. Organizational Necessity

Kondisi yang diperlukan agar manusia dan lembaga dapat menjalankan pekerjaan bersama.

### 3. Repository Necessity

Kondisi yang diperlukan agar artefak, reasoning trail, dan current state dapat disimpan serta ditemukan kembali.

Kesalahan terjadi jika kebutuhan level 2 atau 3 dipromosikan menjadi prinsip Philosophy.

## Repository Tidak Menentukan Philosophy

Git dapat membutuhkan:

- penamaan file;
- folder;
- versioning;
- commit;
- branch;
- metadata.

Semua itu berguna untuk traceability.

Tetapi keberadaan folder atau format tertentu tidak membuktikan bahwa struktur tersebut merupakan bagian dari Philosophy.

`repository structure ≠ philosophical structure`.

## Organisasi Tidak Menentukan Truth

Organisasi juga membutuhkan:

- siapa melakukan review;
- siapa mencatat;
- siapa menjaga akses;
- bagaimana pekerjaan dibagi.

Kebutuhan tersebut tidak otomatis menjadi claim tentang hakikat manusia, kebenaran, atau nilai.

`organizational arrangement ≠ philosophical commitment`.

## Philosophy Tidak Selalu Membutuhkan Organisasi

Sebuah prinsip filosofis dapat tetap benar atau menarik secara argumentatif walaupun organisasi tertentu bubar.

Ini memberikan counterfactual test:

> Jika organisasi TUMBUH tidak ada, apakah alasan filosofis tersebut masih memiliki makna?

Jika ya, kemungkinan ia lebih dekat kepada Philosophy.

Jika tidak, mungkin ia terutama merupakan organizational requirement.

## Repository Counterfactual

Uji yang sama dapat diterapkan terhadap repository:

> Jika Git repository diganti dengan media lain, apakah commitment Philosophy tersebut berubah?

Jika tidak, commitment bukan milik repository.

Repository hanya salah satu materialization.

## Function Independence Test

Sebuah candidate philosophical principle semakin kuat status filosofisnya bila:

- tetap diperlukan di luar organisasi tertentu;
- tidak bergantung pada format repository;
- memiliki alasan yang dapat dibahas secara independen;
- dan menjawab pertanyaan tentang reality, human nature, truth, value, meaning, knowledge, atau normative orientation.

Ini bukan definisi final Philosophy, tetapi diagnostic test.

## Scope Test

Setiap claim harus diberi scope.

Misalnya:

“Semua reasoning harus dapat ditelusuri”

dapat berarti prinsip epistemik.

Tetapi:

“Semua reasoning harus disimpan dalam file Markdown dengan empat digit nomor”

jelas lebih dekat kepada repository convention.

Yang kedua tidak otomatis menjadi Philosophy hanya karena mendukung yang pertama.

## Dependency Direction

Arah dependency juga membantu.

Secara konseptual:

`Philosophy → principles → organizational implications → repository implications`.

Bukan:

`repository convention → organizational rule → philosophical truth`.

Repository dapat memberi evidence bahwa suatu principle diwujudkan, tetapi tidak menjadi sumber pembenaran principle tersebut.

## Practical Instantiation

Satu prinsip Philosophy dapat memiliki banyak instantiation.

Contoh:

`traceability`

dapat diwujudkan melalui:

- Git;
- database;
- buku catatan;
- arsip;
- atau sistem lain.

Jika prinsip tetap sama sementara medium berubah, maka medium bukan bagian dari core philosophical commitment.

## Invariance Test

Ini menghasilkan tes penting:

> Apa yang tetap sama ketika organisasi, medium, prosedur, atau repository berubah?

Yang invariant memiliki peluang lebih besar menjadi bagian dari Philosophy.

Yang berubah karena konteks implementasi kemungkinan lebih dekat kepada methodology atau operations.

## Replacement Test

Ganti:

- Git dengan sistem lain;
- struktur organisasi dengan struktur lain;
- reviewer dengan reviewer lain;
- prosedur dengan prosedur lain.

Kemudian lihat apa yang hilang.

Jika yang hilang adalah kemampuan teknis tetapi philosophical reasoning tetap utuh, maka yang diganti bukan Philosophy.

## Necessary for Inquiry vs Necessary for Work

Perbedaan penting:

`necessary for responsible inquiry`

berbeda dari:

`necessary for efficient work`.

Misalnya kemampuan challenge mungkin terkait dengan integrity inquiry.

Tetapi penggunaan pull request untuk melakukan challenge adalah salah satu implementation choice.

## Necessary for Memory vs Necessary for Philosophy

Traceability dapat menjadi kebutuhan epistemik karena reasoning perlu dapat direkonstruksi.

Tetapi Git commit bukan kebutuhan Philosophy.

Yang mungkin philosophical adalah nilai epistemik dari **provenance dan reconstructability**.

Cara implementasinya tetap terbuka.

## Necessary for Coordination vs Necessary for Truth

Organisasi memerlukan koordinasi.

Tetapi koordinasi tidak menghasilkan truth.

Sebuah keputusan dapat menjadi canonical organizationally tanpa menjadi true philosophically.

Distinction ini konsisten dengan:

`canonical ≠ final`.

## Organizational Convenience Test

Sebuah rule patut dicurigai sebagai organizational rather than philosophical jika alasan utamanya:

- lebih mudah dikelola;
- menghemat waktu;
- memudahkan pembagian tugas;
- mengurangi konflik administratif;
- atau mengikuti kebiasaan organisasi.

Semua alasan tersebut dapat valid.

Tetapi valid secara organizational tidak sama dengan philosophical.

## Philosophical Necessity Test

Sebaliknya, candidate principle lebih dekat kepada Philosophy jika tanpa prinsip tersebut kita kehilangan kemampuan menjawab pertanyaan filosofis tertentu atau kehilangan kondisi yang diperlukan untuk responsible inquiry.

Tetapi bahkan di sini harus diuji apakah prinsip tersebut benar-benar philosophical atau hanya epistemological/organizational derivative.

## Jangan Terlalu Cepat Menaikkan Status

Ada risiko lain:

Karena repository dibangun berdasarkan hasil PROBE, orang dapat menganggap semua yang masuk repository memiliki status Philosophy.

Padahal repository berisi berbagai level:

`philosophical commitment → interpretation → methodology → governance → implementation → record`.

Repository adalah container of provenance, bukan satu tingkat epistemik tunggal.

## Provenance Layer

Maka setiap artefak idealnya dapat menjawab:

> Dari mana klaim ini berasal dan pada level apa ia berada?

Contoh:

`PROBE → philosophical argument → principle → governance implication → repository implementation`.

Dengan provenance, kita tidak perlu menjadikan struktur repository sebagai philosophical authority.

## Repository as Materialization

Repository dapat dipahami sebagai **materialization layer**.

Ia membuat reasoning dapat diwariskan, dibandingkan, dan direvisi.

Tetapi materialization tidak sama dengan origin.

`repository records reasoning; it does not create philosophical justification`.

## Organizational Mediation

Di antara Philosophy dan repository terdapat organisasi.

Organisasi menerjemahkan prinsip menjadi:

- roles;
- workflows;
- review mechanisms;
- responsibilities;
- dan operational constraints.

Terjemahan ini selalu memiliki unsur interpretasi.

Karena itu organizational rule perlu dapat dilacak kembali ke principle yang menjadi alasannya.

## Translation Loss

Setiap translasi berisiko kehilangan makna.

Misalnya:

`corrigibility → review procedure`

dapat berubah menjadi:

“harus mengikuti formulir review.”

Jika formulir kemudian dianggap sebagai corrigibility itu sendiri, terjadi **proxy substitution**.

## Proxy Test

Tanyakan:

> Apakah mekanisme ini benar-benar menjaga kondisi filosofis, atau hanya menjadi proxy yang kemudian diperlakukan sebagai tujuan?

Jika proxy menjadi tujuan, organisasi mulai menggeser Philosophy.

## Over-Philosophizing

Ada juga bahaya sebaliknya.

Tidak semua detail operasional perlu diberi legitimasi filosofis.

Misalnya:

- format nama file;
- jam meeting;
- software yang digunakan;
- pembagian folder.

Semua dapat penting secara praktis, tetapi tidak perlu menjadi “ajaran Philosophy TUMBUH”.

## Under-Philosophizing

Namun jangan pula semua hal diturunkan menjadi sekadar teknis.

Jika organisasi menetapkan bahwa challenge boleh ditutup sepihak, masalahnya mungkin bukan sekadar SOP.

Ia dapat menyentuh commitment epistemik tentang corrigibility dan contestability.

Maka diagnosis harus tetap mengikuti dependency:

`implementation → method → principle → philosophical commitment`.

## Boundary Test

Untuk setiap candidate element, ajukan lima pertanyaan:

1. Apa pertanyaan yang dijawab?
2. Apakah pertanyaan tersebut philosophical, organizational, atau implementation-specific?
3. Apakah alasan element ini tetap berlaku jika organisasi berubah?
4. Apakah element ini dapat diwujudkan dengan mekanisme lain?
5. Apa yang berubah jika element ini dihilangkan?

## Three-Layer Reconstruction

Sebuah artefak dapat direkonstruksi melalui:

`Philosophical reason → organizational translation → repository implementation`.

Jika chain ini jelas, batas antarlevel menjadi lebih mudah dijaga.

## Example: Contestability

Candidate philosophical level:

> Responsible inquiry harus terbuka terhadap challenge yang relevan.

Organizational translation:

> Harus ada jalur untuk mengajukan challenge terhadap current state.

Repository implementation:

> Challenge dapat dicatat sebagai file atau issue dengan provenance tertentu.

Ketiganya terkait.

Tetapi hanya yang pertama merupakan candidate philosophical commitment.

## Example: Traceability

Candidate philosophical/epistemic level:

> Reasoning yang menjadi dasar commitment penting perlu dapat direkonstruksi.

Organizational translation:

> Keputusan perlu memiliki reasoning record.

Repository implementation:

> Reasoning disimpan melalui file, commit, metadata, atau struktur lain.

Sekali lagi, ketiganya tidak memiliki status yang sama.

## Example: Numbering

`P0257` adalah kebutuhan repository untuk identifikasi.

Ia membantu provenance.

Tetapi tidak ada alasan filosofis untuk menganggap empat digit sebagai truth condition.

Jika nomor berubah, Philosophy tidak runtuh.

Ini contoh sederhana tetapi penting.

## Identity Test

Pertanyaan lebih tajam:

> Jika element ini diubah, apakah Philosophy TUMBUH berubah identitasnya atau hanya cara TUMBUH mengorganisasi pekerjaannya?

Jika hanya cara kerja berubah, element tersebut kemungkinan bukan core Philosophy.

## Counterfactual Identity Test

Bayangkan TUMBUH tetap memiliki seluruh philosophical commitments tetapi:

- berganti repository;
- berganti struktur organisasi;
- berganti workflow;
- atau bahkan berganti medium dokumentasi.

Jika identitas Philosophy masih dapat direkonstruksi, maka identitas tersebut berada pada level yang lebih dalam.

## Philosophical Kernel vs Organizational Shell

Muncul metafora sementara:

`philosophical kernel`

berisi commitments dan alasan yang menjaga identitas.

`organizational shell`

berisi cara manusia mengoperasikan commitments tersebut.

`repository layer`

berisi materialization dan memory.

Shell dan layer dapat berubah tanpa otomatis mengubah kernel.

Namun shell dapat menjadi begitu bertentangan dengan kernel sehingga perlu diagnosis filosofis.

## Boundary Is Porous, Not Collapsed

Batas antarlevel bukan tembok kedap.

Organizational failure dapat memberi signal bahwa philosophical principle salah diterjemahkan.

Repository failure dapat mengganggu traceability yang bernilai epistemik.

Tetapi hubungan tersebut tidak berarti semua failure otomatis menjadi philosophical failure.

## Escalation Rule

Ketika masalah muncul, gunakan kembali diagnosis:

`outcome → practice → method → principle → commitment`.

Berhenti pada level terendah yang benar-benar menjelaskan masalah.

Jangan naik ke Philosophy hanya karena masalah terlihat serius.

## Descent Rule

Sebaliknya, jangan turunkan masalah filosofis menjadi SOP hanya karena mudah diperbaiki secara administratif.

Jika perubahan operational mengubah normative force atau structural dependency suatu commitment, inquiry perlu naik level.

## Status Is Also Layered

Status tidak hanya melekat pada Philosophy.

Sebuah repository convention dapat stable secara teknis tetapi tidak memiliki philosophical status.

Sebuah philosophical commitment dapat provisional tetapi tetap menjadi current reference.

Karena itu:

`repository stability ≠ philosophical maturity`.

## Temuan Sementara

1. Kebutuhan Philosophy, organisasi, dan repository harus dibedakan secara eksplisit.
2. Repository structure tidak menentukan philosophical structure.
3. Organizational arrangement tidak menentukan truth.
4. Counterfactual terhadap organisasi dan repository membantu menguji philosophical status.
5. Invariance dan replacement tests dapat menemukan apa yang lebih fundamental.
6. Traceability mungkin merupakan kebutuhan epistemik, tetapi Git bukan kebutuhan Philosophy.
7. Governance merupakan translasi organizational dari kebutuhan inquiry, bukan otomatis philosophical commitment.
8. Proxy substitution dapat terjadi ketika mekanisme operasional dianggap sebagai prinsip itu sendiri.
9. Over-philosophizing sama berbahayanya dengan under-philosophizing.
10. Provenance perlu menjaga rantai `Philosophical reason → organizational translation → repository implementation`.
11. Candidate philosophical kernel berbeda dari organizational shell dan repository layer.
12. Batas antarlevel bersifat porous tetapi tidak boleh collapsed.
13. Diagnosis tetap perlu mengikuti dependency agar masalah tidak salah dinaikkan atau diturunkan.
14. Stability pada repository tidak membuktikan maturity Philosophy.
15. Identity Philosophy lebih mungkin berada pada commitments dan relationships yang tetap invariant ketika organisasi atau medium berubah.

## Rumusan Sementara

> **TUMBUH perlu membedakan philosophical necessity, organizational necessity, dan repository necessity. Philosophy memberi alasan dan orientation; organisasi menerjemahkannya menjadi arrangement dan governance; repository mematerialisasikannya menjadi record dan struktur. Ketiganya saling terhubung tetapi tidak memiliki status epistemik yang sama. Candidate element sebaiknya diuji melalui counterfactual, invariance, replacement, dependency, dan identity tests agar kebutuhan organisasi atau repository tidak diam-diam dipromosikan menjadi Philosophy.**

Rumusan ini masih provisional.

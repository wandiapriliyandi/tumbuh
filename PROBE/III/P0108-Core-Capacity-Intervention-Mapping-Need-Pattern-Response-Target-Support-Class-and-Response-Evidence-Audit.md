# P0108 — Core Capacity Intervention Mapping: Need Pattern, Response Target, Support Class, and Response Evidence Audit

## Status

**PASS — DENGAN GUARDRAIL**

## Tujuan

Menyusun arsitektur konseptual untuk memetakan temuan Core Capacity menuju need pattern, response target, support/intervention class, dan response evidence tanpa mengunci satu metode universal.

## Prinsip Utama

> **Intervention dipilih berdasarkan kebutuhan yang teridentifikasi dan kondisi yang memengaruhinya, bukan berdasarkan label capacity semata.**

## 1. Canonical Mapping Chain

```text
Assessment Evidence
      ↓
Scoped Inference
      ↓
Need Pattern
      ↓
Response Target
      ↓
Support / Intervention Class
      ↓
Implementation
      ↓
Response Evidence
      ↓
Review / Adaptation
```

## 2. Need Pattern ≠ Capacity Deficit

Need pattern menjelaskan apa yang membutuhkan dukungan atau perubahan.

Need dapat berada pada:

- functioning;
- knowledge/skill/resource;
- opportunity;
- demand;
- environment;
- relationship;
- support;
- institutional condition;
- safety condition.

## 3. Response Target

Target intervention harus dipilih berdasarkan bottleneck yang paling relevan terhadap tujuan.

```text
Individual
Task
Opportunity
Environment
Relationship
Support
Institution
Safety
```

Tidak ada aturan bahwa setiap finding harus menghasilkan individual training.

## 4. Support / Intervention Class

Secara konseptual response dapat berupa:

- enabling support;
- skill/resource support;
- environmental adjustment;
- opportunity creation;
- scaffolding;
- coaching/guidance;
- practice opportunity;
- relational support;
- preventive support;
- corrective support;
- recovery/reintegration;
- safeguarding response ketika pathway keselamatan diperlukan.

Daftar ini bukan taxonomy effectiveness dan bukan urutan wajib.

## 5. Capacity-Specific Mapping Guardrails

### Self-Regulation
Need dapat berupa kesempatan monitoring, strategi regulation, adjustment of demand, atau environmental structure.

### Critical Thinking
Need dapat berupa akses informasi, reasoning practice, feedback, task design, atau support terhadap judgment.

### Communication
Need dapat berupa communication opportunity, mode/accessibility, language support, reception/interpretation support, atau relational safety.

### Collaboration
Need dapat berupa role clarity, shared-goal structure, coordination practice, relationship repair, atau team environment adjustment.

### Physical Functioning
Need dapat berupa accessibility, assistive support, physical practice, demand adjustment, atau referral ketika clinical expertise diperlukan.

### Social Understanding
Need dapat berupa contextual explanation, relational support, perspective-taking opportunity, atau environmental adjustment.

### Agency
Need dapat berupa real choice/opportunity, graded responsibility, support fading, barrier removal, atau reduction of unnecessary control.

### Problem Solving
Need dapat berupa problem representation support, resource/knowledge support, strategy practice, feedback, atau adjustment of task complexity.

## 6. Support ≠ Dependency

Support dapat enable functioning dan development.

Dependency harus dinilai terhadap tujuan dan kondisi, bukan diasumsikan dari keberadaan support.

> **Support is not automatically a deficit.**

## 7. Agency Safeguard

Intervention harus menjaga ruang bertindak sejauh aman dan proporsional.

```text
Support
  ↓
Enable Agency

bukan

Support
  ↓
Replace Agency
```

## 8. Least-Burdensome Principle

Jika beberapa response dapat mencapai tujuan yang sebanding, sistem sebaiknya mempertimbangkan response dengan burden lebih rendah.

Namun ini bukan absolute rule; safety dan consequence dapat membenarkan response lebih kuat.

## 9. Response Matching

Response match dinilai dari:

- target fit;
- mechanism fit;
- intensity fit;
- timing fit;
- duration fit;
- context fit;
- burden fit.

Intervention effectiveness tidak dapat diasumsikan dari nama program.

## 10. Response Evidence

Response evidence harus membedakan:

```text
Implementation
→ Immediate Response
→ Functioning Change
→ Performance Change
→ Capacity Change
→ Outcome
```

Perubahan pada satu level tidak otomatis membuktikan perubahan pada level lain.

## 11. Non-Response

Non-response tidak otomatis berarti:

> “capacity-nya lebih rendah.”

atau

> “dosis intervention harus ditambah.”

Possible explanations harus ditinjau:

- wrong target;
- wrong mechanism;
- insufficient opportunity;
- implementation drift;
- context mismatch;
- support mismatch;
- measurement limitation;
- alternative cause.

## 12. Adaptation

Setelah response evidence tersedia, sistem dapat:

- continue;
- adapt;
- intensify;
- reduce;
- pause;
- stop;
- redirect.

Pilihan harus proporsional dan terdokumentasi.

## 13. High-Stakes / Safeguarding

Untuk serious safety concern, safeguarding pathway dapat membutuhkan response khusus.

Namun developmental intervention dan safeguarding response tetap dibedakan.

> **Risk signal ≠ confirmed harm.**

## 14. Muwashofat Boundary

Muwashofat memberi normative direction, tetapi tidak boleh digunakan untuk membenarkan intervention maksimal atau punishment tanpa assessment of need, risk, context, dan proportionality.

## 15. Intervention Mapping Matrix

| Finding pattern | Possible target | Possible response class | Response evidence |
|---|---|---|---|
| Functioning difficulty dengan demand mismatch | Task/demand | Demand adjustment | Functioning under revised demand |
| Functioning terbatas karena opportunity rendah | Opportunity | Opportunity creation | Demonstrability and functioning |
| Resource/skill gap | Resource/skill | Teaching/coaching/practice | Resource use and functioning |
| Support mismatch | Support structure | Scaffold adjustment | Functioning under revised support |
| Environmental barrier | Environment | Environmental modification | Functioning/access change |
| Relational barrier | Relationship | Relational support/repair | Interaction functioning |
| Institutional bottleneck | Institution | System/process adjustment | Implementation and functioning evidence |
| Serious safety concern | Safety | Safeguarding pathway | Safety/recovery evidence |

Matrix ini adalah conceptual mapping, bukan treatment protocol.

## 16. Intervention Boundary

Technical intervention protocols berada di `05_INTERVENTION` dan `06_IMPLEMENTATION`.

P0108 tidak menetapkan:

- universal dose;
- fixed tier;
- mandatory method;
- effectiveness ranking;
- clinical treatment;
- punishment protocol.

## 17. Decision

**PASS — DENGAN GUARDRAIL**

Core Capacity findings dapat dipetakan ke intervention secara sistematis jika:

1. need tidak disamakan dengan deficit;
2. response target ditentukan berdasarkan bottleneck;
3. environment/opportunity/support dipertimbangkan;
4. intervention class tidak dipaksakan sebagai metode tunggal;
5. Agency dan dignity dijaga;
6. burden dan proportionality diperhitungkan;
7. response evidence digunakan untuk adaptation;
8. high-stakes/safeguarding memiliki governance tersendiri.

Tidak ada Core Capacity baru yang diperlukan.

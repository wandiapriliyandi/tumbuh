# P0086 — Core Capacity–Learning, Metacognition, and Developmental Change Boundary Audit

## Status

**PASS — DENGAN GUARDRAIL**

## Tujuan

Menguji batas antara **Learning**, **Metacognition**, dan Core Capacity serta membedakan proses belajar dari perubahan kapasitas dan growth. Audit ini terutama menguji apakah Learning atau Metacognition perlu ditambahkan ke set Core Capacities.

## Prinsip Utama

> **Belajar dapat menghasilkan perubahan pada pengetahuan, strategi, keterampilan, functioning, atau capacity; tetapi Learning sendiri tidak otomatis identik dengan Capacity Change.**

## 1. Learning ≠ Capacity

Learning memiliki beberapa kemungkinan makna: proses memperoleh/mengubah pengetahuan atau kemampuan, perubahan yang dihasilkan, atau outcome pembelajaran. Karena ambiguitas ini, Learning belum memiliki identitas ontologis yang cukup stabil untuk langsung menjadi Core Capacity.

Karena itu:

- learning ≠ capacity;
- learning ≠ performance;
- learning ≠ mastery;
- learning ≠ growth;
- learning ≠ Capacity Change.

Seseorang dapat belajar sesuatu yang spesifik tanpa menunjukkan perubahan broad capacity. Sebaliknya, capacity dapat berkembang melalui pengalaman yang tidak selalu tampil sebagai pembelajaran eksplisit.

## 2. Learning ≠ Practice

Practice dapat menjadi kondisi yang mendukung learning, tetapi repetition atau exposure tidak otomatis menghasilkan learning.

```text
Exposure ≠ Practice ≠ Learning ≠ Capacity Change
```

Hubungan tersebut bersifat konseptual dan tidak boleh dibaca sebagai rantai kausal universal.

## 3. Learning ≠ Skill

Learning dapat menghasilkan skill, pengetahuan, strategi, atau perubahan functioning. Skill adalah kemampuan melakukan aktivitas tertentu; ia tidak otomatis menjadi Core Capacity.

Satu skill dapat mendukung beberapa capacity, dan satu capacity dapat memobilisasi banyak skill.

## 4. Learning ≠ Mastery

Mastery menunjukkan tingkat penguasaan terhadap target tertentu. Mastery dapat tinggi pada satu task tanpa menunjukkan broad capacity change.

Karena itu mastery progression tetap berada di `03_PROGRESSION`, sedangkan technical mastery assessment berada di `04_ASSESSMENT`.

## 5. Learning ≠ Capacity Change

Capacity Change menuntut perubahan pada state/functioning dari Core Capacity, bukan sekadar bertambahnya informasi atau kemampuan task-specific.

Contoh batas:

- menghafal strategi regulasi ≠ otomatis Self-Regulation Change;
- mempelajari aturan argumen ≠ otomatis Critical Thinking Change;
- mempelajari kosakata ≠ otomatis Communication Change;
- mempelajari prosedur kelompok ≠ otomatis Collaboration Change;
- mempelajari teknik gerak ≠ otomatis broad Physical Functioning Change;
- mempelajari norma sosial ≠ otomatis Social Understanding Change;
- mengetahui cara mengambil inisiatif ≠ otomatis Agency Change;
- menghafal algoritma ≠ otomatis Problem Solving Change.

## 6. Metacognition ≠ Core Capacity Secara Otomatis

Metacognition umumnya berkaitan dengan kemampuan memahami, memonitor, dan meregulasi proses kognitif atau belajar sendiri.

Namun sebagian fungsi tersebut memiliki overlap kuat dengan **Self-Regulation** dan sebagian dapat mendukung **Critical Thinking**.

Karena itu Metacognition belum cukup dibuktikan sebagai Core Capacity independen.

Posisi kerja:

> **Metacognition lebih tepat diperlakukan sebagai subfunction/resource atau pola functioning yang dapat mendukung beberapa Core Capacities, dengan status ontologis yang tetap terbuka untuk penelitian.**

## 7. Metacognition ≠ Self-Regulation

Self-Regulation TUMBUH lebih luas: memonitor dan mengatur functioning serta tindakan diri agar tetap atau kembali selaras dengan arah atau tujuan relevan.

Metacognition dapat menjadi bagian dari monitoring terhadap proses berpikir/belajar, tetapi tidak mencakup seluruh Self-Regulation.

Sebaliknya, tidak semua Self-Regulation harus bersifat metacognitive secara eksplisit.

Dengan demikian:

> **Metacognition dapat mendukung Self-Regulation, tetapi Metacognition ≠ Self-Regulation.**

## 8. Metacognition ≠ Critical Thinking

Critical Thinking berfokus pada pemeriksaan, analisis, evaluasi, inferensi, dan penjelasan terhadap informasi atau alasan untuk membentuk judgment.

Metacognition dapat membantu seseorang memonitor kualitas proses berpikirnya, tetapi monitoring proses berpikir bukan keseluruhan Critical Thinking.

Jadi:

- metacognition dapat mendukung Critical Thinking;
- Critical Thinking dapat melibatkan metacognitive monitoring;
- keduanya tidak boleh diperlakukan sebagai sinonim.

## 9. Learning sebagai Resource bagi Core Capacities

Learning dapat menjadi resource penting bagi seluruh Core Capacities.

Contoh:

```text
Learning
  ├── memberi pengetahuan bagi Critical Thinking
  ├── memberi strategi bagi Self-Regulation
  ├── memberi skill bagi Communication
  ├── memberi prosedur bagi Collaboration
  ├── memberi teknik bagi Physical Functioning
  ├── memperkaya Social Understanding
  ├── memperluas opsi bagi Agency
  └── memberi knowledge/strategies bagi Problem Solving
```

Namun relasi ini tidak berarti Learning adalah “super-capacity”. Learning berada pada kategori konseptual yang berbeda dan dapat berfungsi sebagai proses/resource lintas capacity.

## 10. Developmental Change ≠ Learning Event

Satu learning event tidak otomatis menjadi developmental change.

Perubahan perkembangan membutuhkan interpretasi temporal dan konteks yang memadai.

Maka:

```text
Learning Event
      ↓
Possible Change in Knowledge / Skill / Functioning
      ↓
Possible Capacity Change
      ↓
Potential Growth
```

Panah di atas menunjukkan kemungkinan konseptual, bukan hubungan kausal otomatis.

## 11. Transfer sebagai Guardrail

Learning pada satu task tidak otomatis ditransfer ke konteks lain.

Karena itu:

- task learning ≠ broad capacity;
- near transfer ≠ far transfer;
- transfer ≠ proof of capacity change;
- no transfer in one context ≠ absence of capacity.

Temuan ini konsisten dengan P0057 dan P0073.

## 12. Familiarity dan Learned Procedure

Familiarity dengan tugas dapat meningkatkan performance tanpa broad capacity change.

Demikian pula penggunaan prosedur yang telah dipelajari tidak otomatis menunjukkan Problem Solving, Critical Thinking, atau Self-Regulation pada tingkat yang lebih tinggi.

Assessment harus membedakan:

- knowledge of procedure;
- execution of procedure;
- flexible use;
- functioning under variation;
- broader capacity inference.

## 13. Learning dan J1–J4

J1–J4 tidak diperlakukan sebagai tahapan belajar universal atau developmental stage.

Jika learning berubah menurut tingkat support/autonomy, perubahan tersebut harus dibaca sebagai hubungan antara learning conditions, support, opportunity, dan functioning—bukan sebagai bukti bahwa J1–J4 adalah tahapan psikologis universal.

## 14. Implikasi terhadap Progression

Progression harus menjelaskan perubahan functioning Core Capacity dari waktu ke waktu dan terhadap demand yang relevan.

Learning progression dapat berjalan paralel dengan Capacity Progression, tetapi keduanya tidak boleh dilebur.

```text
Capacity
   ↕
Capacity Progression

Learning
   ↕
Learning Progression

Mastery
   ↕
Mastery Progression
```

Hubungan antarlapis perlu dijelaskan secara eksplisit tanpa mengasumsikan satu selalu menyebabkan yang lain.

## 15. Implikasi terhadap Assessment

Nilai ujian, jumlah materi dikuasai, penyelesaian modul, atau keberhasilan mengingat informasi tidak boleh dijadikan proxy tunggal untuk Core Capacity.

Assessment harus menentukan intended inference terlebih dahulu.

Jika tujuan assessment adalah Capacity, evidence harus merepresentasikan construct dan functional dimensions, bukan hanya learning outcome.

Technical assessment tetap berada di `04_ASSESSMENT` dan `09_RESEARCH`.

## 16. Implikasi terhadap Intervention

Jika capacity functioning rendah, respons tidak otomatis berupa “lebih banyak pembelajaran”.

Sistem harus membedakan apakah kebutuhan berada pada:

- knowledge;
- skill;
- practice;
- feedback;
- Self-Regulation;
- opportunity;
- support;
- environment;
- task demand;
- relationship;
- atau capacity functioning itu sendiri.

Sebaliknya, intervensi pembelajaran dapat menjadi salah satu jalan menuju perubahan capacity bila kondisi dan mekanismenya mendukung, tetapi efektivitasnya tetap merupakan pertanyaan empiris.

## 17. Apakah Learning Perlu Menjadi Core Capacity?

**Belum. Status tetap HOLD.**

Alasan utama:

1. identitas ontologis Learning masih ambigu;
2. dapat menunjuk process, change, outcome, atau ability;
3. hubungan dengan capacity bersifat lintas-level;
4. learning dapat menjadi resource bagi banyak capacity;
5. menjadikannya Core Capacity berisiko membuat taxonomy terlalu luas dan mengaburkan bridge antara capacity dan development.

Keputusan ini tidak menolak pentingnya learning. Justru learning tetap merupakan bagian fundamental dari sistem pendidikan dan progression TUMBUH.

## 18. Apakah Metacognition Perlu Menjadi Core Capacity?

**Belum. Tidak ditambahkan sebagai Core Capacity independen.**

Posisi kerja:

- dapat menjadi subfunction;
- dapat menjadi resource;
- dapat mendukung Self-Regulation;
- dapat mendukung Critical Thinking;
- dapat menjadi pola functioning penting dalam learning;
- tetap terbuka untuk penelitian ontologis lebih lanjut.

Tidak diperlukan Core Model baru.

## Decision

**PASS — DENGAN GUARDRAIL**

Tidak ada Core Capacity yang perlu ditambahkan atau dihapus berdasarkan audit ini.

Delapan provisional Core Capacities tetap:

1. Self-Regulation
2. Critical Thinking
3. Communication
4. Collaboration
5. Physical Functioning
6. Social Understanding
7. Agency
8. Problem Solving

Tetap di luar set independen:

- Learning — HOLD
- Metacognition — subfunction/resource/pattern candidate, bukan Core Capacity independen
- Decision Making — HOLD / integrative functioning pattern
- Adaptability — HOLD / integrative pattern
- Resilience — HOLD / emergent pattern
- Empathy — non-independent Core Capacity

## Epistemic Status

**DESIGNED / CONCEPTUAL ARCHITECTURAL INQUIRY**

Audit ini menetapkan boundary konseptual dan keputusan arsitektural sementara. Ia bukan bukti empiris atau kausal tentang bagaimana learning, metacognition, dan capacity change selalu berhubungan pada semua konteks.

# P0110 — Core Capacity Intervention–Implementation Integration: Tiered Support, Decision Architecture, and Case Management Audit

## Status

**PASS — DENGAN GUARDRAIL**

## Tujuan

Menguji hubungan Core Capacity intervention mapping dengan prinsip Intervention, Tiered Support, Decision Architecture, dan Case Management tanpa menjadikan capacity score sebagai tiket otomatis menuju tier, treatment, atau label kasus.

## Prinsip Utama

> **Tier dan case management mengatur intensitas serta koordinasi respons; keduanya bukan ontology baru tentang kapasitas manusia.**

## 1. Canonical Integration

```text
Assessment Evidence
      ↓
Scoped Inference
      ↓
Need / Risk / Opportunity Analysis
      ↓
Response Decision
      ↓
Support / Intervention Tier
      ↓
Implementation / Case Management
      ↓
Response Evidence
      ↓
Review / Adaptation
```

## 2. Tier ≠ Capacity Level

Tiered Support tidak boleh dibaca sebagai:

```text
Tier 3 = Capacity rendah
Tier 2 = Capacity sedang
Tier 1 = Capacity tinggi
```

Tier menjelaskan **intensitas/jenis dukungan**, bukan level ontologis manusia.

## 3. Tier Selection

Pemilihan tier harus mempertimbangkan:

- need;
- risk;
- opportunity;
- context;
- available support;
- response history;
- burden;
- consequence.

Tidak cukup hanya menggunakan satu capacity score.

## 4. Universal / Targeted / Intensive Support

Secara konseptual support dapat dibedakan menjadi:

- universal/preventive support;
- targeted support;
- intensive/individualized support;
- safeguarding response ketika safety pathway diperlukan.

Ini adalah architecture of response, bukan ranking peserta.

## 5. Need ≠ Deficit

Seseorang dapat membutuhkan support karena:

- demand tinggi;
- opportunity rendah;
- environmental barrier;
- temporary state;
- relational condition;
- skill/resource gap;
- safety concern.

Support need tidak otomatis menunjukkan low Core Capacity.

## 6. Decision Architecture

Decision harus mempertimbangkan:

```text
Evidence
+ Interpretation
+ Need
+ Risk
+ Opportunity
+ Context
+ Burden
+ Alternatives
      ↓
Response Decision
```

Tidak ada automatic mapping:

```text
Score → Tier → Intervention
```

## 7. Case Management

Case management diperlukan ketika kebutuhan membutuhkan koordinasi lintas:

- people;
- roles;
- interventions;
- contexts;
- time;
- services/support.

Case management bukan diagnosis dan bukan label capacity.

## 8. Case ≠ Person

```text
Case
≠
Person
```

Case adalah unit koordinasi untuk tujuan tertentu.

Satu orang dapat memiliki kebutuhan berbeda pada waktu/konteks berbeda tanpa menjadi “tipe kasus” permanen.

## 9. Escalation

Escalation harus berdasarkan perubahan need/risk/response, bukan semata label.

```text
Current Response
      ↓
New Evidence
      ↓
Review
      ↓
Maintain / Escalate / De-escalate / Redirect
```

Escalation bukan hukuman.

## 10. De-Escalation

Support dapat dikurangi ketika sesuai dengan tujuan, safety, functioning, dan context.

Tetapi:

> **De-escalation ≠ proof of capacity growth.**

Demikian juga kebutuhan support berkelanjutan ≠ proof of capacity deficit.

## 11. Implementation Fidelity

Tier decision harus dibedakan dari fidelity intervention.

Jika response tidak menghasilkan perubahan, evaluasi harus memeriksa:

- target;
- mechanism;
- delivery;
- context;
- support;
- measurement.

## 12. Coordination Risk

Case management dapat menambah risiko:

- excessive data sharing;
- role confusion;
- duplicated intervention;
- conflicting demands;
- dependency;
- stigma.

Karena itu koordinasi harus tetap purpose-limited dan role-relevant.

## 13. Data Governance

Case information harus mengikuti:

- data minimization;
- purpose limitation;
- access control;
- confidentiality;
- correction;
- review;
- retention governance.

Tidak semua anggota sistem membutuhkan semua data.

## 14. Voice and Agency

Case management harus memberi ruang voice yang sesuai.

Participation tidak berarti unlimited veto atau unlimited disclosure.

Namun:

> **Silence ≠ consent.**

> **Compliance ≠ consent.**

Agency harus dipertimbangkan ketika menentukan support dan transition.

## 15. Safeguarding Boundary

Jika serious safety concern muncul, safeguarding pathway dapat memerlukan escalation yang lebih kuat.

Namun:

> **Risk signal ≠ confirmed harm.**

Developmental case management tidak menggantikan safeguarding investigation.

## 16. Cross-Capacity Cases

Satu case dapat melibatkan beberapa Core Capacities.

Contoh:

```text
Case Need
 ↙   ↓   ↘
Agency  Self-Regulation  Communication
         ↓
   Collaboration
```

Ini tidak membuatnya menjadi satu super-capacity.

## 17. Muwashofat Boundary

Tier, case, atau intervention tidak boleh digunakan untuk memberi label moral berdasarkan 10 Muwashofat.

Muwashofat tetap normative/graduate orientation.

## 18. High-Consequence Response

Untuk response dengan consequence tinggi, diperlukan:

- stronger evidence;
- review;
- documentation;
- proportionality;
- opportunity for correction/voice;
- reversibility where possible.

## 19. Failure Modes

Architecture harus menolak:

1. tier = capacity level;
2. score = automatic intervention;
3. case = person identity;
4. escalation = punishment;
5. support need = deficit;
6. de-escalation = proof of growth;
7. data sharing tanpa purpose;
8. intensive intervention sebagai default;
9. non-response = individual failure;
10. Muwashofat = intervention score.

## 20. Decision

**PASS — DENGAN GUARDRAIL**

Core Capacity dapat diintegrasikan dengan Tiered Support, Decision Architecture, dan Case Management jika:

- tier mengatur response, bukan capacity ontology;
- case menjadi unit koordinasi, bukan identity;
- need/risk/context menjadi dasar decision;
- response target dapat berada pada individual maupun environment;
- escalation/de-escalation dapat direview;
- data tetap purpose-limited;
- Agency dan dignity dijaga;
- safeguarding tetap memiliki pathway tersendiri.

Tidak ada Core Capacity baru yang diperlukan.

## Epistemic Status

**DESIGNED / CONCEPTUAL INTERVENTION–IMPLEMENTATION INTEGRATION AUDIT**

Audit ini tidak memvalidasi efektivitas tier, case management model, atau intervention tertentu.

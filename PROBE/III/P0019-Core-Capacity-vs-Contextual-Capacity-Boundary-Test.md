# P19 — Core Capacity vs Contextual Capacity Boundary Test

## 1. Status

- Probe: **P19**
- Area: Capacity Architecture
- Nature: ontological boundary / taxonomy stress test
- Status: **PASS — STRONG**

---

## 2. Pertanyaan Utama

P15 menetapkan prinsip **stable functional identity, variable contextual expression**.

P18 kemudian membersihkan candidate ontology dan menegaskan bahwa label "Capacity" tidak boleh diberikan kepada semua construct yang penting.

P19 menguji kembali boundary tersebut dengan pertanyaan:

> **Bagaimana membedakan Core Capacity dari kemampuan yang hanya muncul sebagai contextual skill, contextual competency, behavior, atau program-specific functioning?**

Tujuannya adalah menghasilkan boundary yang dapat digunakan secara konsisten ketika taxonomy berkembang.

---

## 3. Working Definition

> **Core Capacity adalah functional developmental construct dengan identity cukup stabil untuk dikembangkan dan dimobilisasi pada lebih dari satu context, walaupun manifestation dapat berbeda.**

Definisi ini tetap provisional dan tidak diklaim sebagai definisi universal.

---

## 4. Core Capacity vs Contextual Expression

Struktur dasar:

```text
CORE CAPACITY
      ↓
Context / Demand / Opportunity / Support
      ↓
Functioning
      ↓
Behavior / Performance
```

Contextual expression adalah cara Capacity bekerja dalam kondisi tertentu.

Ia tidak otomatis merupakan Capacity baru.

---

## 5. Boundary Principle 1 — Context ≠ Capacity

Context menyediakan kondisi tempat functioning berlangsung.

Contoh:

- classroom;
- dormitory;
- family;
- community;
- digital environment.

Tidak satu pun otomatis menjadi Capacity.

---

## 6. Boundary Principle 2 — Behavior ≠ Capacity

Behavior adalah tindakan yang dapat diamati.

Satu behavior dapat melibatkan beberapa Capacity.

```text
Behavior
↙   ↓   ↘
C1  C2   C3
```

Karena itu perilaku tertentu tidak boleh langsung diberi nama Capacity baru.

---

## 7. Boundary Principle 3 — Skill ≠ Core Capacity

Skill biasanya lebih dekat pada kemampuan melakukan task tertentu.

Contoh:

> public speaking menggunakan struktur presentasi tertentu.

Ini lebih tepat sebagai skill/manifestation di bawah Communication daripada otomatis menjadi Core Capacity baru.

---

## 8. Boundary Principle 4 — Competency ≠ Core Capacity

Competency dapat menggambarkan kemampuan memenuhi tuntutan tertentu dengan memobilisasi berbagai resources.

```text
Capacity
+ Knowledge
+ Skill
+ Context
→ Competent performance
```

Diagram tersebut konseptual dan bukan formula universal.

Competency tidak otomatis menjadi ontology Capacity.

---

## 9. Boundary Principle 5 — Value ≠ Capacity

Value memberikan normative direction.

```text
Value
→ what is worth / right / desirable

Capacity
→ what functional ability is developing
```

Value dapat mengarahkan penggunaan Capacity tanpa menjadi Capacity itu sendiri.

---

## 10. Boundary Principle 6 — Character ≠ Capacity

Character dapat memengaruhi cara Capacity dimobilisasi.

Tetapi character tidak otomatis merupakan Capacity.

```text
Character
↕
Capacity
↓
Functioning
```

Hubungan ini konseptual; bukan causal claim.

---

## 11. Boundary Principle 7 — Capacity dapat dimobilisasi dalam Competency

Satu competency dapat menggunakan beberapa Capacity.

Contoh:

```text
Leadership competency
├── Communication
├── Self-Regulation
├── Social Understanding
├── Critical Thinking
└── Collaboration
```

Ini bukan bukti bahwa Leadership harus menjadi Core Capacity.

---

## 12. Boundary Principle 8 — Contextual Manifestation

Capacity dapat muncul dalam bentuk berbeda.

Contoh:

```text
Critical Thinking
├── classroom discussion
├── kajian kitab
├── problem sosial
└── digital information
```

Context mengubah task dan expression, bukan otomatis identity construct.

---

## 13. Boundary Principle 9 — Religious Practice

Religious practice tidak boleh direduksi menjadi generic Capacity hanya agar mudah dimasukkan ke taxonomy.

Contoh:

```text
Ibadah
Adab
Amanah
```

memiliki posisi normative/practice yang perlu dipahami dalam worldview TUMBUH.

Tidak otomatis menjadi generic psychometric Capacity.

---

## 14. Boundary Principle 10 — Definition/Function, bukan Nama

Sebuah construct tidak menjadi Capacity karena namanya mengandung:

- ability;
- skill;
- competency;
- capacity;
- intelligence;
- resilience.

Yang menentukan adalah:

```text
Definition
+
Functional identity
+
Developmental role
+
Boundary
```

---

## 15. Core Capacity Test A — Cross-Context Identity

Pertanyaan:

> Apakah functional identity masih dapat dikenali ketika context berubah?

Jika ya, candidate lebih kuat sebagai Core Capacity.

Jika tidak, candidate cenderung contextual construct.

---

## 16. Core Capacity Test B — Cross-Task Identity

Tidak cukup hanya lintas context.

Candidate juga perlu memiliki identity yang tidak runtuh ketika task berubah.

```text
Task A
Task B
Task C
↓
Same functional identity?
```

Jika hanya satu task, kemungkinan besar skill atau competency.

---

## 17. Core Capacity Test C — Non-Dependence on One Program

Jika construct hanya ada karena program tertentu:

```text
Program X
→ Construct X
```

maka perlu dicurigai sebagai program-specific outcome atau skill.

Core Capacity harus lebih stabil daripada program.

---

## 18. Core Capacity Test D — Evidence Diversity

Core Capacity yang dimaksud lintas context idealnya dapat memiliki evidence dari lebih dari satu context.

Ini bukan berarti setiap assessment wajib menguji semua context.

Tetapi ontology yang mengklaim cross-context relevance harus terbuka terhadap evidence lintas context.

---

## 19. Core Capacity Test E — Developmental Continuity

Candidate harus memungkinkan pembahasan perubahan dari waktu ke waktu.

```text
State t1
↓
State t2
↓
State t3
```

Jika construct hanya outcome satu event, ia bukan kandidat kuat.

---

## 20. Core Capacity Test F — Functional Distinction

Candidate harus memiliki fungsi yang dapat dibedakan dari Capacity yang sudah ada.

Contoh:

```text
Communication
≠
Collaboration
```

walaupun keduanya dapat berinteraksi.

---

## 21. Core Capacity Test G — Non-Reduction to Behavior

Jika candidate dapat didefinisikan hanya sebagai kumpulan behavior:

```text
"sering melakukan X, Y, Z"
```

maka ontology-nya lemah.

Capacity harus menjelaskan functional ability yang berada di balik berbagai manifestation.

---

## 22. Core Capacity Test H — Non-Reduction to Performance

Performance tinggi dalam satu task tidak cukup.

```text
Performance ↑
≠
Capacity ↑
```

Interpretation membutuhkan evidence dan context.

---

## 23. Core Capacity Test I — Support Sensitivity

Core Capacity dapat berfungsi dengan tingkat support berbeda.

```text
Independent functioning
Supported functioning
Assisted functioning
```

Perbedaan ini tidak otomatis menciptakan Capacity baru.

---

## 24. Core Capacity Test J — Opportunity Sensitivity

Capacity mungkin tidak terlihat ketika opportunity tidak tersedia.

```text
No opportunity
≠
No capacity
```

Ini merupakan guardrail penting dalam assessment.

---

## 25. Public Speaking Example

Public speaking dapat memiliki beberapa komponen:

- Communication;
- Self-Regulation;
- Critical Thinking;
- knowledge;
- specific presentation skill.

Karena itu:

> **Public speaking lebih mungkin diperlakukan sebagai skill/contextual competency di bawah Communication daripada Core Capacity tersendiri.**

Keputusan ini tetap terbuka untuk revisi jika research menunjukkan functional identity yang benar-benar berbeda.

---

## 26. Boarding Adaptation Example

"Boarding adaptation" menggambarkan functioning dalam context boarding/pesantren.

Ia dapat melibatkan:

- Adaptability;
- Self-Regulation;
- Social Understanding;
- Communication;
- environmental support.

Karena itu boarding adaptation **tidak otomatis menjadi Core Capacity baru**.

---

## 27. Critical Thinking dalam Kajian Kitab

Critical Thinking dapat digunakan dalam kajian kitab.

Context:

```text
Kajian kitab
```

tidak mengubahnya menjadi:

```text
"Kitab Critical Thinking Capacity"
```

Functional identity tetap Critical Thinking; context hanya mengubah evidence/task.

---

## 28. Academic Self-Regulation

"Academic Self-Regulation" dapat menjadi contextual manifestation dari Self-Regulation.

Pertanyaan yang lebih tepat:

> bagian mana yang merupakan general Self-Regulation dan bagian mana yang merupakan academic-specific strategy?

Dengan demikian context-specific naming perlu diurai sebelum membuat construct baru.

---

## 29. Digital Literacy Example

Digital literacy dapat mencakup:

- knowledge;
- technical skill;
- critical evaluation;
- communication;
- self-regulation.

Karena heterogen, label tersebut tidak otomatis menjadi satu Core Capacity.

Ia dapat lebih tepat ditempatkan sebagai competency/domain-specific construct tergantung definisinya.

---

## 30. Leadership Example

Leadership dapat merupakan:

- competency;
- role;
- behavior;
- social function;
- atau integrative capacity.

P19 tidak memutuskan final status Leadership.

Justru ia menunjukkan mengapa Leadership perlu diuji lebih lanjut berdasarkan functional identity, bukan popular usage.

---

## 31. Agency Example

Agency dapat melintasi:

- intention;
- action;
- autonomy;
- opportunity;
- constraints.

Karena itu Agency adalah kandidat yang kuat tetapi harus dibedakan dari Self-Regulation, Decision Making, dan environmental opportunity.

P19 mempertahankan statusnya sebagai candidate, bukan final Capacity.

---

## 32. Adaptability Example

Adaptability lebih mudah memenuhi cross-context test:

```text
Academic change
Social change
Environmental change
Role change
```

Namun overlap dengan Self-Regulation dan flexibility tetap harus diuji.

---

## 33. Core Capacity vs Contextual Capacity Matrix

| Criterion | Core Capacity | Contextual construct |
|---|---|---|
| Functional identity | relatively stable | strongly context-bound |
| Context | multiple contexts possible | usually one/few contexts |
| Task | multiple tasks possible | often task-specific |
| Development | meaningful over time | may be short-term/performance-based |
| Evidence | can be diversified | often context-specific |
| Program dependence | low | potentially high |
| Skill dependence | not reducible to one skill | often skill-linked |
| Ontological utility | high | usually subordinate |

---

## 34. Boundary Is a Spectrum

P19 tidak menganggap semua construct hanya:

```text
Core
vs
Not Core
```

Ada kemungkinan:

```text
Core Capacity
↓
Contextualized Capacity expression
↓
Competency
↓
Skill
↓
Behavior / Performance
```

Batas antar-level tetap harus dijaga secara konseptual.

---

## 35. Spectrum ≠ Ontological Blur

Mengakui spectrum tidak berarti semua construct boleh bercampur.

Setiap construct tetap harus mempunyai:

- definition;
- scope;
- boundary;
- relation;
- evidence logic.

Ini kembali ke Construct Registry.

---

## 36. Contextual Capacity sebagai Istilah Hati-hati

Istilah "Contextual Capacity" sendiri dapat menimbulkan kebingungan.

Ia bisa berarti:

1. Capacity yang hanya teramati pada context tertentu;
2. Capacity yang benar-benar context-bound;
3. contextualized functioning;
4. competency.

Karena itu TUMBUH sebaiknya tidak menggunakan istilah **Contextual Capacity** sebagai class final tanpa definisi yang lebih ketat.

Lebih aman menggunakan:

> **contextual manifestation / contextualized functioning**

untuk kebanyakan kasus.

---

## 37. Important Distinction

```text
Context-specific evidence
≠
Context-specific ontology
```

Assessment dapat mengambil evidence dari satu context tanpa menyimpulkan bahwa construct hanya ada di context tersebut.

---

## 38. Another Important Distinction

```text
Context-specific intervention
≠
Context-specific Capacity
```

Intervention dapat disesuaikan dengan lingkungan tanpa mengubah target ontology.

---

## 39. Another Important Distinction

```text
Context-specific skill
≠
Context-specific Core Capacity
```

Skill yang sangat spesifik dapat tetap berfungsi sebagai resource bagi Core Capacity yang lebih general.

---

## 40. Parsimony Test

Jika context-specific construct dapat dijelaskan sebagai:

```text
Core Capacity
+
Context
+
Skill / competency
```

maka tidak perlu membuat Capacity baru.

Ini adalah prinsip **minimum sufficient ontology**.

---

## 41. Coverage Test

Parsimony tidak boleh menghasilkan ontology terlalu sempit.

Jika candidate tidak dapat dijelaskan dengan Capacity yang ada tanpa kehilangan functional identity yang penting, candidate perlu dipertimbangkan sebagai Capacity tersendiri.

Dengan demikian:

```text
Parsimony
↔
Coverage
```

harus diuji bersama.

---

## 42. Research Test

Boundary P19 perlu diuji melalui:

- content validity;
- construct validity;
- discriminant validity;
- cross-context evidence;
- longitudinal evidence;
- implementation evidence.

P19 sendiri belum menyediakan hasil empiris tersebut.

---

## 43. Falsification Conditions

P19 harus direvisi jika:

1. construct yang dianggap contextual ternyata memiliki identity lintas context yang kuat;
2. construct yang dianggap Core ternyata hanya muncul karena context tertentu;
3. boundary Capacity–competency tidak dapat dipertahankan;
4. evidence menunjukkan taxonomy terlalu datar;
5. atau taxonomy terlalu fragmented.

---

## 44. Epistemic Status

P19:

- **DESIGNED / CONCEPTUAL**;
- boundary criteria = provisional;
- no universal taxonomy claim;
- no psychometric validation;
- no causal claim;
- examples are architectural illustrations, not empirical classifications.

---

## 45. Keputusan

### **PASS — STRONG**

Core Capacity dapat dibedakan dari contextual construct secara defensible jika identity-nya:

- cukup stabil lintas context;
- tidak bergantung pada satu task;
- tidak identik dengan behavior/performance;
- tidak sekadar skill/competency;
- memiliki developmental relevance;
- dan memiliki architectural utility.

---

## 46. Prinsip yang Dikunci

> **Context ≠ Capacity.**

> **Context-specific evidence ≠ context-specific ontology.**

> **Context-specific intervention ≠ context-specific Capacity.**

> **Skill ≠ Core Capacity.**

> **Competency ≠ Core Capacity.**

> **Functional identity lebih penting daripada nama construct.**

> **Contextual manifestation lebih aman daripada ontological multiplication.**

> **Parsimony harus selalu diseimbangkan dengan coverage.**

> **"Contextual Capacity" bukan class final sampai definisinya benar-benar jelas.**

---

## 47. Dampak Arsitektural

P19 memperkuat boundary:

```text
Core Capacity
      ↓
Contextualized Functioning
      ↓
Competency / Skill
      ↓
Behavior / Performance
      ↓
Evidence
```

Bukan semua layer tersebut harus selalu muncul sebagai rantai linear.

Struktur ini adalah alat pembeda ontology dan evidence.

---

## Ringkasan Keputusan

**P19 = PASS — STRONG.** Core Capacity harus mempunyai functional identity yang cukup stabil lintas lebih dari satu context dan lebih dari satu task, sementara contextual manifestation dapat berubah. Public speaking lebih tepat diperlakukan sebagai skill/contextual competency di bawah Communication; boarding adaptation tidak otomatis menjadi Capacity; dan Critical Thinking dalam kajian kitab tetap merupakan manifestation Critical Thinking. P19 juga mengunci bahwa context-specific evidence, intervention, atau skill tidak otomatis menghasilkan context-specific ontology. Istilah "Contextual Capacity" sendiri belum aman dijadikan class final; **contextual manifestation/contextualized functioning** lebih presisi untuk sementara.

# P28 — Problem Solving Identity & Non-Equivalence Test

## 1. Status

- Probe: **P28**
- Area: Capacity Architecture
- Nature: construct identity / boundary / redundancy stress test
- Status: **PASS — REVISED**
- Epistemic status: conceptual architectural decision; not empirical validation of Problem Solving as a universal Core Capacity

## 2. Pertanyaan utama

P28 menguji apakah **Problem Solving** memiliki functional identity yang cukup berbeda dari Critical Thinking, Self-Regulation, Agency, Decision Making, dan Adaptability untuk dipertahankan sebagai candidate Core Capacity.

Pertanyaan kedua:

> Apakah Problem Solving sebenarnya hanya kombinasi proses dari capacities yang sudah ada, sehingga tidak perlu menjadi construct tersendiri?

## 3. Working definition

Untuk probe ini:

> **Problem Solving adalah kapasitas untuk memahami dan menangani kesenjangan antara kondisi yang ada dan kondisi yang dituju dengan mengidentifikasi hambatan, menghasilkan atau memilih strategi, serta menyesuaikan tindakan berdasarkan informasi dan hasil yang diperoleh.**

Definisi ini masih provisional.

## 4. Functional identity

Inti Problem Solving bukan sekadar berpikir, memilih, atau bertindak.

Functional core-nya adalah:

```text
Current state
      ↓
Recognized gap / problem
      ↓
Understand constraints
      ↓
Generate / evaluate possible approaches
      ↓
Act on a strategy
      ↓
Monitor result
      ↓
Revise when needed
```

Yang menjadi pusat adalah **menangani problem secara terarah**, bukan satu subproses kognitif tertentu.

## 5. Problem Solving ≠ Problem

Problem adalah kondisi/gap/demand yang harus ditangani.

Problem Solving adalah capacity untuk menangani problem tersebut.

```text
Problem
≠
Problem Solving
```

## 6. Problem Solving ≠ Solution

Solution adalah hasil atau strategi yang dipilih.

Seseorang dapat menemukan solution secara kebetulan tanpa memiliki Problem Solving yang kuat.

Karena itu outcome tidak boleh disamakan dengan capacity.

## 7. Problem Solving ≠ Performance

Berhasil menyelesaikan satu masalah tidak otomatis membuktikan kapasitas tinggi.

Sebaliknya, gagal pada satu task tidak otomatis membuktikan kapasitas rendah karena hasil dapat dipengaruhi oleh:

- knowledge;
- resources;
- task difficulty;
- time;
- support;
- opportunity;
- context.

## 8. Problem Solving ≠ Critical Thinking

Critical Thinking berfokus pada pemeriksaan, analisis, evaluasi, inferensi, dan pembentukan judgment.

Problem Solving berfokus pada **menangani gap/problem menuju kondisi yang dituju**.

Critical Thinking dapat digunakan dalam Problem Solving untuk:

- memeriksa informasi;
- mengevaluasi diagnosis;
- menilai alternatif;
- menguji alasan.

Tetapi tidak semua Critical Thinking diarahkan pada penyelesaian problem.

```text
Critical Thinking
→ quality of examination / judgment

Problem Solving
→ handling a problem toward a relevant state
```

## 9. Problem Solving ≠ Reasoning

Reasoning adalah relasi inferensial dari informasi/premis menuju kesimpulan.

Problem Solving dapat menggunakan reasoning, tetapi membutuhkan lebih dari reasoning:

- problem framing;
- strategy generation;
- action;
- monitoring;
- revision.

Karena itu reasoning lebih tepat diposisikan sebagai cognitive function/process, bukan pengganti otomatis Problem Solving.

## 10. Problem Solving ≠ Decision Making

Decision Making berpusat pada pemilihan tindakan/option.

Problem Solving mencakup ruang yang lebih luas:

```text
Problem Solving
→ define/understand problem
→ develop approaches
→ choose
→ act
→ monitor
→ revise
```

Decision Making dapat menjadi salah satu component di dalamnya.

Tetapi tidak semua decision adalah problem solving.

## 11. Problem Solving ≠ Self-Regulation

Self-Regulation mengatur proses diri dan tindakan menuju tujuan.

Problem Solving memiliki object yang lebih spesifik: **problem/gap yang harus ditangani**.

Self-Regulation dapat membantu seseorang:

- bertahan pada problem;
- mengatur perhatian;
- mengendalikan impuls;
- memonitor proses.

Namun regulation sendiri tidak menjawab problem apa yang harus diselesaikan atau strategi apa yang relevan.

## 12. Problem Solving ≠ Agency

Agency berkaitan dengan menginisiasi dan mengarahkan tindakan secara intentional.

Problem Solving membutuhkan tindakan, tetapi tindakan tersebut diarahkan pada handling a problem.

```text
Agency
→ initiate / direct action

Problem Solving
→ use action to address a problem
```

Seseorang dapat agentic dalam aktivitas yang bukan problem solving.

## 13. Problem Solving ≠ Adaptability

Adaptability berfokus pada reconfiguration ketika kondisi berubah.

Problem Solving berfokus pada penanganan gap/problem.

Adaptability dapat membantu ketika strategi problem solving gagal atau kondisi berubah.

Namun seseorang dapat memecahkan problem tanpa perubahan konteks yang berarti.

## 14. Problem Solving ≠ Learning

Problem Solving dapat menghasilkan learning.

Learning juga dapat meningkatkan kemampuan problem solving.

Tetapi keduanya bukan construct yang sama.

```text
Problem Solving
→ activity/capacity of addressing problems

Learning
→ change/acquisition that may result from experience
```

## 15. Problem Solving ≠ Knowledge

Knowledge tentang domain tertentu sangat membantu problem solving.

Namun memiliki knowledge tidak menjamin seseorang mampu menggunakannya untuk menangani problem.

Sebaliknya, seseorang dapat menunjukkan problem solving dasar dengan knowledge terbatas melalui strategi dan resource yang tepat.

## 16. Problem Solving ≠ Skill

Specific techniques such as:

- mathematical procedures;
- troubleshooting procedure;
- conflict-resolution technique;
- coding debugging technique;

adalah skills atau domain-specific competencies.

Problem Solving, jika dipertahankan, harus berada pada level functional yang lebih abstrak.

## 17. Problem Solving ≠ Intelligence

General cognitive ability dapat mendukung Problem Solving.

Tetapi Problem Solving tidak identik dengan intelligence karena keberhasilannya dipengaruhi oleh knowledge, context, strategy, motivation, opportunity, dan experience.

## 18. Problem Solving ≠ Creativity

Generating novel alternatives dapat menjadi bagian dari Problem Solving.

Tetapi kreativitas juga dapat digunakan tanpa adanya problem yang harus diselesaikan.

Karena itu Creativity dan Problem Solving tidak equivalent.

## 19. Problem Solving ≠ Resilience

Resilience berfokus pada maintaining/recovering functioning under adversity.

Problem Solving berfokus pada addressing a problem.

Resilience dapat membantu persistence dalam problem solving, tetapi bukan pengganti construct.

## 20. Problem Solving ≠ Compliance

Mengikuti prosedur yang sudah diberikan bukan otomatis Problem Solving.

Jika solution dan procedure sudah sepenuhnya ditentukan, yang terlihat mungkin lebih dekat pada skill execution atau compliance.

Problem Solving menjadi lebih jelas ketika individu harus memahami problem dan menentukan atau menyesuaikan approach.

## 21. Problem Solving dan problem framing

Problem framing penting karena kesalahan memahami problem dapat menghasilkan tindakan yang tidak relevan.

Namun framing bukan keseluruhan Problem Solving.

Ia merupakan salah satu component/subfunction yang dapat muncul dalam problem solving process.

## 22. Problem Solving dan strategy generation

Kemampuan menghasilkan strategi adalah bagian penting, tetapi tidak identik dengan Problem Solving.

Seseorang dapat menghasilkan banyak strategi tanpa mampu memilih, menjalankan, dan mengevaluasinya.

## 23. Problem Solving dan action

Problem Solving tidak harus berarti physical action.

Action dapat berupa:

- mencari informasi;
- mengubah prosedur;
- meminta bantuan;
- menguji alternatif;
- mengubah keputusan;
- menyusun ulang langkah.

Karena itu Problem Solving tidak dibatasi pada “melakukan sendiri”.

## 24. Problem Solving dan help-seeking

Meminta bantuan dapat menjadi bagian dari Problem Solving yang baik jika dilakukan secara intentional dan relevan terhadap problem.

Dengan demikian independence tidak boleh menjadi definisi wajib Problem Solving.

## 25. Problem Solving dan transfer

Problem Solving yang lebih kuat seharusnya tidak hanya muncul pada satu task yang sangat familiar.

Tetapi transfer tidak berarti harus universal ke semua domain.

Yang diuji adalah apakah functional identity dapat muncul pada lebih dari satu relevant context.

## 26. Context sensitivity

Problem solving sangat dipengaruhi oleh:

- domain knowledge;
- task demand;
- resources;
- time;
- social environment;
- support;
- prior experience.

Karena itu performance evidence harus selalu dibaca bersama context.

## 27. Core vs contextual manifestation

Contoh:

- memperbaiki keran rusak;
- menyelesaikan konflik kelompok;
- menemukan strategi belajar ketika nilai turun;
- menangani perubahan jadwal kegiatan.

Keempatnya berbeda task, tetapi dapat memunculkan functional core yang sama:

> memahami problem, mengembangkan/memilih approach, bertindak, memonitor, dan menyesuaikan.

Task-specific skill tetap bukan Core Capacity.

## 28. Relationship with Critical Thinking

Relationship dapat dirumuskan:

```text
Critical Thinking
→ helps determine whether diagnosis/reasons/alternatives are sound

Problem Solving
→ uses such judgment to address a problem
```

Ini adalah hubungan konseptual, **bukan klaim kausal empiris**.

## 29. Relationship with Decision Making

Decision Making dapat menjadi node penting dalam Problem Solving.

Tetapi jika Decision Making nanti dipertahankan sebagai candidate Capacity, keduanya perlu dibedakan:

```text
Decision Making
→ selecting among options/actions

Problem Solving
→ addressing a problem, which may require one or several decisions
```

## 30. Relationship with Agency

Agency memberi intentional initiation/direction.

Problem Solving memberi problem-oriented direction.

Keduanya dapat co-occur tetapi memiliki functional object berbeda.

## 31. Relationship with Adaptability

Ketika initial solution tidak efektif:

```text
Problem
↓
Attempt
↓
Feedback
↓
Need to revise strategy
```

Adaptability dapat membantu revision.

Tetapi kemampuan menyelesaikan problem tetap lebih luas daripada kemampuan adaptasi saja.

## 32. Relationship with Self-Regulation

Self-Regulation membantu mengelola:

- attention;
- effort;
- emotion;
- persistence;
- monitoring.

Problem Solving menggunakan regulation tersebut untuk tetap menangani problem.

Ini mendukung distinctness tetapi juga menunjukkan overlap struktural.

## 33. Problem Solving as integrative capacity

P28 menemukan bahwa Problem Solving secara alami mengintegrasikan beberapa fungsi:

```text
Problem Solving
├── problem framing
├── information use
├── reasoning
├── strategy generation
├── decision
├── action
├── monitoring
└── revision
```

Ini tidak berarti setiap komponen harus dimiliki dalam bentuk identik pada semua kasus.

Problem Solving adalah functional construct, bukan anatomy universal.

## 34. Apakah integrative berarti bukan Capacity?

Tidak.

P17 sudah menetapkan bahwa Capacity dapat memiliki heterogenitas internal.

Karena itu status integrative tidak otomatis menggugurkan Problem Solving.

Yang diuji adalah apakah kombinasi fungsi tersebut membentuk functional identity yang stabil.

## 35. Risk of over-expansion

Problem Solving berisiko menjadi “super-capacity” yang menyerap:

- Critical Thinking;
- Decision Making;
- Self-Regulation;
- Agency;
- Adaptability;
- Creativity.

Karena itu batasnya harus tegas.

## 36. Boundary rule

Problem Solving tidak boleh didefinisikan sebagai:

> “semua kemampuan yang digunakan ketika seseorang menghadapi masalah.”

Definisi seperti itu terlalu luas dan membuat construct tidak falsifiable secara arsitektural.

Functional identity harus tetap pada **problem-oriented handling**.

## 37. Assessment implications

Evidence yang lebih kuat dapat melihat:

1. apakah problem/gap dikenali;
2. apakah problem dipahami secara memadai;
3. apakah constraints diperhitungkan;
4. apakah approach dikembangkan/dipilih;
5. apakah tindakan sesuai dengan problem;
6. apakah hasil dimonitor;
7. apakah strategy direvisi bila diperlukan.

P28 tidak menetapkan instrument atau rubric tertentu.

## 38. False positive risk

Hal berikut tidak otomatis menunjukkan Problem Solving:

- mengikuti contoh;
- menghafal prosedur;
- menebak jawaban;
- berhasil karena kebetulan;
- memiliki knowledge tinggi tanpa problem-oriented action.

## 39. False negative risk

Kegagalan menyelesaikan problem tidak otomatis berarti Problem Solving rendah.

Problem mungkin:

- terlalu sulit;
- kurang informasi;
- tidak tersedia resources;
- dibatasi authority;
- membutuhkan expertise yang belum dimiliki;
- membutuhkan bantuan eksternal.

## 40. Developmental relevance

Problem Solving dapat berkembang melalui:

- pengalaman problem yang beragam;
- guided practice;
- feedback;
- reflection;
- increasing complexity;
- kesempatan memilih strategi;
- kesempatan memperbaiki kesalahan.

Ini compatible dengan Growth Mechanism interaktif.

## 41. Normative direction

Problem Solving sendiri tidak menentukan apakah solution itu baik secara moral.

Arah normatif tetap berasal dari Foundation dan Graduate Profile.

```text
Problem Solving
→ effectiveness / appropriateness in handling problem

Normative direction
→ whether the chosen direction is educationally/value-relevant
```

Dengan demikian effectiveness ≠ goodness.

## 42. Architectural necessity test

Jika Problem Solving dihapus sebagai label, fungsi problem-oriented handling masih harus dijelaskan.

Ada dua kemungkinan:

1. cukup dijelaskan sebagai kombinasi Critical Thinking + Self-Regulation + Agency + Decision Making + Adaptability;
2. kombinasi tersebut menghasilkan explanatory loss karena tidak memiliki satu functional object yang jelas.

P28 menemukan kemungkinan kedua cukup kuat secara konseptual, tetapi belum merupakan bukti empiris.

## 44. Main redundancy finding

P28 **tidak menemukan equivalence penuh** antara Problem Solving dan capacities lain.

Namun Problem Solving adalah construct integrative sehingga redundancy risk tetap tinggi jika definisinya terlalu luas.

Karena itu construct harus dijaga pada functional object:

> **addressing a problem/gap through understanding, strategy, action, monitoring, and revision.**

## 45. Relation to P23

P23 meminta minimal sufficient set.

P28 menunjukkan bahwa validitas individual Problem Solving cukup kuat, tetapi itu belum berarti ia harus masuk set final.

```text
Individual validity
≠
Set-level necessity
```

## 46. Relation to P24

P24 mencari coverage gap.

Problem-oriented functioning merupakan territory yang belum sepenuhnya tertutup hanya dengan Critical Thinking, Self-Regulation, Agency, dan Adaptability.

Tetapi coverage harus diuji lagi setelah seluruh candidate capacities dipetakan.

## 47. Relation to P27

P27 menunjukkan Adaptability sebagai strong candidate dengan redundancy unresolved.

P28 memperjelas:

```text
Adaptability
→ reconfigure when conditions change

Problem Solving
→ address a problem/gap
```

Perubahan kondisi dapat memicu problem solving, tetapi keduanya bukan construct yang sama.

## 48. What P28 establishes

P28 menetapkan:

1. Problem Solving memiliki functional identity yang dapat dipertahankan.
2. Problem Solving ≠ Critical Thinking.
3. Problem Solving ≠ Decision Making.
4. Problem Solving ≠ Self-Regulation.
5. Problem Solving ≠ Agency.
6. Problem Solving ≠ Adaptability.
7. Problem Solving ≠ Reasoning, Learning, Knowledge, Skill, Intelligence, Creativity, atau Resilience.
8. Problem Solving bersifat integrative tetapi tetap dapat memiliki functional identity.
9. Context dan resource penting dalam interpretasi evidence.
10. Problem Solving memiliki architectural utility yang cukup kuat.

## 49. What P28 does not establish

P28 belum menetapkan bahwa:

- Problem Solving pasti menjadi Core Capacity final;
- Problem Solving harus menjadi assessment domain tersendiri;
- semua problem solving dapat diukur dengan satu instrument;
- Problem Solving universal lintas budaya/domain;
- keberhasilan menyelesaikan masalah sama dengan Capacity tinggi;
- Problem Solving menyebabkan Growth;
- semua component di dalamnya adalah Capacity.

## 50. Final decision

**PASS — REVISED.**

Problem Solving dipertahankan sebagai **strong candidate Core Capacity**, dengan guardrail bahwa construct tidak boleh menjadi super-capacity yang menyerap Critical Thinking, Decision Making, Self-Regulation, Agency, atau Adaptability.

Status final inclusion tetap menunggu **set-level parsimony + coverage + evidence audit**.

## 51. Working candidate set

```text
CORE CAPACITY — PROVISIONAL / CANDIDATE
│
├── Self-Regulation
├── Critical Thinking
├── Communication
├── Collaboration
├── Physical Functioning
├── Social Understanding  [provisional]
├── Agency                [strong candidate]
├── Adaptability          [strong candidate / unresolved]
└── Problem Solving       [strong candidate]
```

Jumlah ini **belum final**.

## 52. Governance rule

Problem Solving tidak boleh menjadi tempat penampungan semua kemampuan yang digunakan dalam menghadapi masalah.

Setiap subfunction harus tetap memiliki identity dan hubungan yang dapat ditelusuri di Construct Registry.

Jika kemudian Problem Solving dikeluarkan dari set final, functional territory-nya wajib dipetakan secara eksplisit ke construct pengganti beserta explanatory-cost analysis.

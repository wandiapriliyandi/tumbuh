# P0104 — Core Capacity–Progression–Assessment Traceability Matrix and Component Boundary Audit

## Status

**PASS — DENGAN GUARDRAIL**

## Tujuan

Menyusun traceability matrix konseptual dari delapan Core Capacities menuju progression dimensions, milestone, intended inference, evidence requirements, dan assessment components tanpa menciptakan scoring ontology baru.

## Prinsip

> **Assessment component harus dapat ditelusurkan kembali ke construct dan progression; tidak boleh sebaliknya.**

## Canonical Chain

```text
Core Capacity
→ Functional Object
→ Functional Dimensions
→ Progression Dimensions
→ Milestone / Developmental Marker
→ Intended Inference
→ Evidence Requirements
→ Assessment Component
→ Scoped Judgment
```

## Traceability Matrix

| Core Capacity | Functional dimensions | Progression focus | Evidence requirement | Assessment component boundary |
|---|---|---|---|---|
| Self-Regulation | Monitoring; Regulation; Reorientation | breadth, consistency, adjustment, support profile | evidence of monitoring/regulation/reorientation across relevant demands | component harus menangkap functioning, bukan compliance score |
| Critical Thinking | Examination/Analysis; Evaluation; Inference/Judgment; Explanation/Justification | quality, complexity, consistency, flexibility | evidence of examining/evaluating/inferencing/explaining reasons or claims | component tidak direduksi menjadi academic score |
| Communication | Formulation; Expression/Transmission; Reception; Interpretation | adequacy, context range, reciprocity, adjustment | evidence across formation, transmission, reception, interpretation | component tidak direduksi menjadi speaking test |
| Collaboration | Contribution; Coordination; Joint Adjustment | coordination complexity, consistency, flexibility | evidence of contribution and joint adjustment toward shared goals | component tidak direduksi menjadi group outcome |
| Physical Functioning | Mobility/Movement; Manipulation/Control; Endurance/Function relative to Demand | adequacy relative to demand, safety, accessibility | evidence under relevant physical demands and conditions | component tidak menjadi universal sport score |
| Social Understanding | Perspective Interpretation; Relational Interpretation; Social-Context Interpretation | complexity, breadth, contextual adequacy | evidence of interpreting perspectives, relations, social contexts | component tidak menjadi popularity/empathy score |
| Agency | Initiation; Direction; Intentional Action under Conditions | breadth of initiative, direction under constraints, adjustment | evidence of intentional initiation/direction in real conditions | component tidak menjadi independence score |
| Problem Solving | Problem Representation; Strategy Generation/Selection; Action Adjustment | complexity, strategy flexibility, adjustment, transfer | evidence across representation, strategy, and action adjustment | component tidak menjadi task-count score |

## 1. Component Boundary

Assessment component dapat berupa sumber, task, observation, interview, work sample, record, atau bentuk evidence lain.

Namun:

> **Assessment component ≠ Core Capacity.**

Satu component dapat menghasilkan evidence untuk beberapa constructs, tetapi intended inference harus tetap jelas.

## 2. Milestone Traceability

Setiap milestone harus memiliki hubungan eksplisit:

```text
Milestone
→ Functional Dimension
→ Developmental Change
→ Evidence Pattern
```

Milestone yang hanya berbentuk “perilaku baik” harus ditolak atau direvisi.

## 3. Evidence Requirement

Evidence requirement menjelaskan informasi apa yang diperlukan untuk intended inference.

Ia bukan instrumen tertentu.

```text
Evidence Requirement ≠ Instrument
```

## 4. Assessment Component Selection

Pemilihan component dilakukan setelah intended inference ditentukan.

```text
Intended Inference
      ↓
Evidence Requirement
      ↓
Component Selection
```

Bukan:

```text
Available Instrument
      ↓
Score
      ↓
Construct
```

## 5. Coverage Test

Sebuah assessment architecture dianggap underrepresented bila component hanya menangkap sebagian kecil functional identity.

Contoh:

- Self-Regulation hanya dari attendance/discipline;
- Critical Thinking hanya dari multiple-choice score;
- Communication hanya dari oral presentation;
- Collaboration hanya dari final group product;
- Physical Functioning hanya dari fitness result;
- Social Understanding hanya dari peer popularity;
- Agency hanya dari independence;
- Problem Solving hanya dari answer correctness.

Component tersebut mungkin berguna, tetapi inference harus dibatasi.

## 6. Context Requirement

Traceability harus mempertimbangkan:

- context;
- demand;
- opportunity;
- support;
- constraint;
- familiarity;
- language/culture;
- technology;
- state/health;
- role/power.

Tidak semua factor harus selalu diukur; yang diperlukan bergantung pada intended inference.

## 7. Temporal Requirement

Jika assessment digunakan untuk progression, evidence perlu memiliki temporal relevance.

Satu event tidak otomatis cukup untuk developmental claim.

```text
Event Evidence
   ≠
Progression Evidence automatically
```

## 8. Support Requirement

Assessment harus mencatat support ketika support materially memengaruhi intended inference.

Support tidak boleh otomatis diperlakukan sebagai contamination.

Sebaliknya, unsupported functioning tidak boleh otomatis dianggap lebih valid.

## 9. Cross-Source Evidence

Untuk intended inference yang luas, evidence dapat berasal dari beberapa source/context.

Perbedaan source tidak otomatis harus dirata-ratakan.

Disagreement dapat menjadi informasi tentang context dependence atau measurement limitation.

## 10. Gateway Traceability

Gateway harus memiliki chain:

```text
Gateway Purpose
→ Required Functioning
→ Evidence Sufficiency
→ Transition Decision
```

Gateway tidak boleh menjadi:

```text
Score ≥ X → Person Ready
```

kecuali operational threshold tersebut telah memiliki justification dan evidence yang sesuai di layer Assessment/Research.

## 11. High-Stakes Boundary

Semakin besar consequence transition, semakin tinggi kebutuhan untuk:

- evidence diversity;
- contextual interpretation;
- uncertainty disclosure;
- review;
- voice/correction opportunity;
- reversibility.

## 12. Scoring Boundary

Assessment dapat menggunakan scoring untuk kebutuhan operasional.

Tetapi score adalah representation of evidence/judgment, bukan ontological identity of capacity.

> **Score ≠ Capacity itself.**

## 13. Personhood Boundary

Assessment output harus tetap diposisikan sebagai scoped information.

```text
Assessment Profile ≠ Person
Assessment Judgment ≠ Identity
Capacity Level ≠ Human Worth
```

## 14. Muwashofat Boundary

10 Muwashofat tetap normative/graduate orientation.

Traceability capacity tidak boleh menghasilkan implicit moral score.

Mapping normative-to-functional tetap many-to-many dan non-causal.

## 15. Technical Boundary

P0104 tidak menetapkan:

- item bank;
- rubric final;
- numerical weights;
- universal thresholds;
- psychometric model;
- reliability coefficient;
- validity coefficient;
- sampling count.

Semua itu berada pada Assessment/Research.

## 16. Decision

**PASS — DENGAN GUARDRAIL**

Traceability matrix dapat menjadi canonical bridge antara Core Capacity, Progression, dan Assessment dengan syarat:

1. construct tetap menjadi anchor;
2. functional dimensions tidak berubah menjadi score domains secara otomatis;
3. milestone tetap developmental marker;
4. evidence requirement tetap berbeda dari instrument;
5. assessment component tidak didefinisikan sebagai construct;
6. inference scope membatasi claim scope;
7. context/support diperhitungkan;
8. high-stakes decisions mendapat governance lebih kuat.

Tidak ada Core Capacity baru yang diperlukan.

## Epistemic Status

**DESIGNED / CONCEPTUAL TRACEABILITY ARCHITECTURE**

Matrix ini belum merupakan validated assessment blueprint.

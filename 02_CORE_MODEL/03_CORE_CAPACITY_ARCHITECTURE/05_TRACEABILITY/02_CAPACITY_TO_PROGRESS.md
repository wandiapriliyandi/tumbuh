# Capacity to Progression Trace

## Gampangnya

Trace ini memastikan bahwa **Core Capacity tidak langsung berubah menjadi daftar usia atau indikator**, tetapi diterjemahkan melalui struktur progression yang jelas.

## Canonical Chain

```text
Core Capacity
      ↓
Progression Dimension
      ↓
Milestone
      ↓
Purpose-Specific Gateway
      ↓
Evidence-Based Transition Criteria
```

## Prinsip

### 1. Capacity tetap stabil
Progression tidak boleh mengubah definisi Core Capacity hanya karena bentuk functioning berubah pada tahap perkembangan berbeda.

### 2. Manifestasi dapat berubah
Cara suatu capacity tampak dapat berbeda menurut usia, konteks, pengalaman, tuntutan, dan dukungan.

### 3. Milestone bukan capacity baru
Milestone menggambarkan perkembangan yang relevan pada progression tertentu, bukan construct tambahan.

### 4. Gateway harus purpose-specific
Kriteria transisi dibuat untuk tujuan perkembangan tertentu. Tidak boleh dianggap sebagai bukti universal bahwa seseorang telah "menguasai" seluruh capacity.

## Boundary

Progression tidak boleh:

- mengganti construct dengan checklist usia;
- menganggap perkembangan selalu linear;
- menyamakan performance satu tugas dengan capacity;
- atau membuat klaim universal tanpa evidence.

## Contoh Logika

```text
Self-Regulation
      ↓
Monitoring
      ↓
Milestone perkembangan
      ↓
Evidence dalam konteks relevan
      ↓
Transition decision untuk tujuan tertentu
```

## Status

**Conceptually specified / empirically provisional.**

# Core Capacity Traceability

## Purpose

Traceability memastikan setiap Core Capacity dapat ditelusuri dari arah normatif dan mekanisme pertumbuhan sampai ke progression, assessment, intervention, dan evidence tanpa mencampur level konstruk.

## Canonical Chain

```text
Worldview / Normative Direction
        ↓
Graduate Profile
        ↓
Core Capacity
        ↓
Functional Object
        ↓

        ↓

        ↓

        ↓

        ↓
Assessment
        ↓
Intervention
        ↓

        ↓
Evidence & Research
        ↺
Continuous Improvement
```

## Core Capacity Identity

Setiap capacity minimal dapat ditelusuri melalui:

- canonical name;
- definition;
- functional object;
- functional dimensions;
- boundaries;
- contextual conditions;
- relationships to other capacities;
- evidence territory;
- normative traceability;
- validation status;
- source trail.

## Layer Boundaries

### Normative Direction
Menentukan arah dan tujuan yang dianggap bernilai. Tidak boleh disamakan dengan capacity.

### Core Capacity
Menjelaskan functional capacity yang menjadi objek perubahan pertumbuhan. Tidak boleh diganti oleh indikator atau program.

### Functional Object & Dimensions
Menjelaskan struktur internal capacity. Tidak boleh berubah menjadi task, instrument, atau rubric secara diam-diam.

### Observable Manifestations & Evidence
Menunjukkan bagaimana functioning dapat diamati atau dibuktikan dalam konteks tertentu. Evidence bukan construct itu sendiri.

### Progression
Menjelaskan perubahan functioning sepanjang perkembangan atau tuntutan. Progression bukan definisi capacity.

### Assessment
Menghasilkan evidence dan inference sesuai tujuan assessment. Assessment bukan definisi construct.

### Intervention
Merespons kondisi berdasarkan interpretation dan evidence. Intervention tidak boleh mendefinisikan ulang capacity.

### Implementation
Mengatur bagaimana sistem dijalankan. Implementasi tidak menjadi bukti otomatis bahwa construct atau intervensi efektif.

## Traceability Requirements

1. Tidak ada capacity baru hanya karena muncul indikator atau program baru.
2. Tidak ada indicator yang diperlakukan sebagai definisi capacity.
3. Tidak ada normative construct yang diam-diam diperlakukan sebagai capacity.
4. Tidak ada performance pada satu task yang diperlakukan sebagai representasi seluruh capacity.
5. Tidak ada hasil lokal yang otomatis dinaikkan menjadi klaim universal.
6. Tidak ada claim causal/effectiveness tanpa evidence yang sesuai.
7. Status validasi harus selalu terlihat.

## Governance Links

```text
Construct Registry
      ↓
Claim Registry
      ↓
Evidence Registry
      ↓
Decision Log
      ↓
Domain Specifications
```

Perubahan definisi, boundary, dimensions, atau hubungan capacity harus meninggalkan jejak pada governance layer dan tidak dilakukan hanya melalui perubahan program atau assessment.

## Validation Status

Traceability architecture berstatus **conceptually specified / empirically provisional**. Ia merupakan mekanisme governance untuk menjaga konsistensi lintas-layer, bukan bukti empiris dengan sendirinya.

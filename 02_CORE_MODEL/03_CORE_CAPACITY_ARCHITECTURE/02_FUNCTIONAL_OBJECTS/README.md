# Functional Objects

## Purpose

Functional Object menjelaskan **apa yang menjadi objek functioning** dari sebuah Core Capacity. Ia menjadi jembatan antara nama capacity yang masih abstrak dan Functional Dimensions yang menjelaskan fungsi di dalamnya.

## Canonical Rule

```text
Core Capacity
→ Functional Object
→ Functional Dimensions
→ Subfunctions / Resources / Patterns
→ Observable Manifestations
→ Evidence
```

Functional Object bukan indikator, bukan task, bukan instrument, dan bukan evidence.

## Canonical Mapping

| Core Capacity | Functional Object |
|---|---|
| Self-Regulation | Functioning dan tindakan diri relatif terhadap arah atau tujuan yang relevan |
| Critical Thinking | Informasi, alasan, dan judgment yang relevan bagi apa yang diyakini atau dilakukan |
| Communication | Message formation, transmission, reception, dan meaning |
| Collaboration | Joint action dan contribution menuju shared goals |
| Physical Functioning | Physical functioning yang diperlukan untuk menjalankan aktivitas atau memenuhi tuntutan konteks |
| Social Understanding | Keadaan, perspektif, relasi, dan konteks sosial yang relevan bagi functioning |
| Agency | Intentional initiation dan direction of action under real conditions |
| Problem Solving | Gap antara kondisi aktual dan kondisi yang dituju, beserta hambatan dan strategi untuk menanganinya |

## Boundary

Functional Object tidak boleh diperluas menjadi:

- domain program;
- metode pembelajaran;
- indikator penilaian;
- task tertentu;
- alat ukur;
- atau konstruk normatif baru.

## Governance

Perubahan Functional Object harus konsisten dengan definisi canonical Core Capacity, Functional Dimensions, boundaries, dan traceability yang telah ditetapkan. Jika perubahan mengubah identitas atau ruang lingkup capacity, perubahan harus diperlakukan sebagai revisi construct, bukan sekadar edit deskripsi.

## Validation Status

Arsitektur ini berstatus **conceptually specified / empirically provisional**.

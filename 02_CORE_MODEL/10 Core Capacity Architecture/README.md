# Core Capacity Architecture

## Status

**DESIGNED — v2.0.0**

## Purpose

Core Capacity Architecture menjelaskan bagaimana delapan Core Capacities TUMBUH disusun, dibedakan, dihubungkan, dan ditelusurkan tanpa menjadikannya satu skor total atau hierarchy of human worth.

## Canonical Set

1. Self-Regulation
2. Critical Thinking
3. Communication
4. Collaboration
5. Physical Functioning
6. Social Understanding
7. Agency
8. Problem Solving

Status seluruh construct: **architecturally specified, empirically provisional**.

## Capacity Relationship Architecture

Relationships antar-capacity bersifat **functional and relational**, bukan otomatis causal, additive, atau hierarchical.

A capacity dapat:

- mendukung capacity lain;
- dipengaruhi oleh functioning capacity lain;
- co-occur dalam aktivitas;
- menjadi complementary;
- menjadi constraining dalam kondisi tertentu;
- berkontribusi pada integrative functioning pattern.

```text
CC-A ↔ CC-B ↔ CC-C
  ↕       ↕       ↕
Context / Demand / Opportunity / Support
```

Panah tidak berarti causal proof.

## Functional Object Map

| Capacity | Functional Object |
|---|---|
| Self-Regulation | Functioning/tindakan diri relatif terhadap arah/tujuan |
| Critical Thinking | Informasi, claims, reasons, judgment |
| Communication | Message formation, transmission, reception, meaning |
| Collaboration | Joint action dan contribution menuju shared goals |
| Physical Functioning | Physical function relatif terhadap demand |
| Social Understanding | States, perspectives, relations, social contexts |
| Agency | Initiation/direction of own action under conditions |
| Problem Solving | Discrepancy current–desired state |

## Decomposition Rule

```text
Core Capacity
    ↓
Functional Object
    ↓
Functional Dimension
    ↓
Subfunction / Resource
    ↓
Observable Manifestation
    ↓
Evidence
```

Tidak semua elemen pada level bawah harus ada untuk setiap capacity dengan bentuk yang sama.

Prinsip governance:

> **TUMBUH membutuhkan aturan decomposition yang konsisten, bukan anatomi psikologis yang seragam.**

## Cross-Capacity Boundaries

### Core Capacity ≠ Process
Learning, practice, reflection, feedback, dan adaptation dapat menjadi process perkembangan.

### Core Capacity ≠ Mechanism
Growth Mechanism menjelaskan proses/interaksi yang memungkinkan perubahan; ia bukan taxonomy capacity.

### Core Capacity ≠ Resource
Knowledge, skill, strategy, tool, scaffold, dan compensation dapat mendukung functioning.

### Core Capacity ≠ Pattern
Decision Making, Adaptability, dan Resilience dapat diposisikan sebagai integrative/emergent functioning patterns tanpa menjadi capacity baru.

### Core Capacity ≠ Normative Construct
Aqidah, ibadah, adab, akhlak, values, dan 10 Muwashofat tetap pada normative/profile level.

## Context Architecture

Capacity identity harus cukup stabil lintas konteks, tetapi manifestation dapat berubah menurut:

- context;
- task/demand;
- opportunity;
- constraint;
- support;
- familiarity;
- state;
- culture/language;
- technology;
- role/power.

```text
Stable Functional Identity
          ↓
Dynamic Functioning
          ↓
Contextual Manifestation
```

## Evidence Architecture

Evidence bukan construct.

Canonical inference:

```text
Evidence
  ↓
Interpretation
  ↓
Construct-relevant Inference
  ↓
Scoped Assessment Judgment
  ↓
Decision
```

Claim scope tidak boleh melebihi evidence scope.

Single indicator, single task, single observer, atau single context tidak otomatis mewakili keseluruhan capacity.

## Progression Boundary

Core Capacity menjawab **apa yang berkembang**.

Progression menjawab **bagaimana functioning berubah sepanjang waktu atau tuntutan**.

Progression tidak boleh mengubah capacity menjadi:

- universal stage;
- age norm;
- maturity score;
- ranking;
- fixed identity.

## Intervention Boundary

Assessment tidak otomatis menentukan intervention.

Response dapat diarahkan pada:

- capacity functioning;
- skill/knowledge;
- task demand;
- opportunity;
- environment;
- relationship;
- support;
- institutional condition.

Capacity training bukan default response untuk setiap performance difficulty.

## Normative Traceability

10 Muwashofat tetap menjadi normative/graduate orientation.

Mapping ke Core Capacities bersifat:

- many-to-many;
- functional;
- provisional;
- non-causal;
- non-scoring.

Tidak boleh terjadi back-fitting sehingga setiap Muwashofat dipaksa menjadi capacity.

## Governance Principles

1. **Construct First** — jangan mulai dari instrument.
2. **Boundary Before Expansion** — uji overlap sebelum menambah construct.
3. **Functional Object First** — tetapkan objek fungsi sebelum decomposition.
4. **Dimension ≠ Indicator**.
5. **Evidence ≠ Construct**.
6. **Pattern ≠ Capacity**.
7. **Context ≠ New Capacity**.
8. **Normative Direction ≠ Capacity Score**.
9. **Capacity Profile ≠ Person**.
10. **Capacity Level ≠ Human Worth**.
11. **Empirical status must remain visible**.
12. **Future evidence may revise the architecture**.

## Status and Validation

**Architectural status:** CLOSED FOR CURRENT CONCEPTUAL SPECIFICATION.

**Empirical status:** PROVISIONAL.

Belum ada klaim bahwa delapan capacity merupakan taxonomy psikometrik universal, invariant lintas budaya, atau causal theory.

## Revision Trigger

Architecture dapat dibuka kembali jika research/evidence menunjukkan:

- construct redundancy material;
- construct underrepresentation;
- blind spot developmental yang material;
- poor discriminability;
- failure of intended inference;
- cross-context instability yang tidak dapat dijelaskan secara memadai;
- atau kebutuhan normatif/functional baru yang benar-benar memenuhi ontological criteria.

Perubahan harus ditelusurkan melalui Construct Registry, Claim Registry, Evidence Registry, dan Design Decision Record.

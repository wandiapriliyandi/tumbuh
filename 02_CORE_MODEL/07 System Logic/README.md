# 02_CORE_MODEL / 07 System Logic

**Status:** DESIGNED — Wave 2 baseline

## Purpose

Menjelaskan logika hubungan antarkomponen inti TUMBUH tanpa mengubah domain yang sudah didefinisikan dalam Foundation, Graduate Profile, Capacity Architecture, Capacity Taxonomy, Capacity Relationships, Triad Growth Architecture, dan Development Domains.

## System Logic

Alur desain inti TUMBUH:

**Worldview → Human Nature → Graduate Profile → Capacity Architecture → Development Domains → Capacity Taxonomy → Progression → Assessment → Intervention → Implementation → Evidence & Research → Continuous Improvement**

Alur tersebut bukan klaim hubungan kausal otomatis. Setiap hubungan harus dibedakan antara hubungan normatif, konseptual, desain, empiris, atau kausal sesuai klasifikasi epistemik TUMBUH.

## Decision Logic

1. Tetapkan arah melalui Graduate Profile.
2. Terjemahkan arah menjadi kapasitas yang dapat didefinisikan.
3. Tempatkan kapasitas dalam domain perkembangan dan hubungan antarkapasitas.
4. Rancang progression dan milestone yang sesuai konteks.
5. Kumpulkan evidence melalui assessment multi-sumber.
6. Gunakan hasil assessment untuk menentukan kebutuhan dukungan.
7. Pilih intervention yang proporsional dan beradab.
8. Implementasikan melalui educator, caregiver, keluarga, program, kebijakan, dan sistem institusi.
9. Pantau fidelity, respons, outcome, risiko, dan unintended effects.
10. Gunakan evidence dan hasil evaluasi untuk memperbaiki desain.

## Boundary

System Logic tidak menggantikan:

- definisi construct;
- rubrik atau instrumen assessment;
- prosedur intervention;
- SOP implementasi;
- program pendidikan tertentu;
- bukti empiris tentang efektivitas.

Dokumen ini adalah representasi logika sistem, bukan bukti bahwa seluruh hubungan telah tervalidasi secara empiris.

# Functional Objects

## Purpose

Functional Object menjelaskan **apa yang menjadi objek functioning** dari sebuah Core Capacity. Ia menjadi jembatan antara nama capacity yang masih abstrak dan Functional Dimensions yang menjelaskan fungsi di dalamnya.

Functional Object harus cukup spesifik untuk membatasi ruang konstruk, tetapi tidak terlalu spesifik hingga berubah menjadi task, indikator, atau instrumen.

## Canonical Representation

```text
Core Capacity
→ Functional Object
→ Functional Dimensions
→ Subfunctions / Resources / Patterns
→ Observable Manifestations
→ Evidence
```

Rantai tersebut adalah struktur representasi konstruk, bukan urutan perkembangan atau prosedur assessment.

## Canonical Mapping

| Core Capacity | Functional Object |
|---|---|
| Self-Regulation | Functioning dan tindakan diri relatif terhadap arah atau tujuan yang relevan |
| Critical Thinking | Informasi, klaim, alasan, dan judgment yang relevan bagi apa yang diyakini atau dilakukan |
| Communication | Pembentukan, penyampaian, penerimaan, dan pemaknaan pesan dalam interaksi |
| Collaboration | Tindakan bersama dan kontribusi yang terkoordinasi menuju tujuan bersama |
| Physical Functioning | Functioning fisik yang diperlukan untuk menjalankan aktivitas atau memenuhi tuntutan konteks |
| Social Understanding | Keadaan, perspektif, relasi, dan konteks sosial yang relevan bagi functioning |
| Agency | Inisiasi dan pengarahan tindakan secara sengaja dalam kondisi nyata |
| Problem Solving | Kesenjangan antara kondisi aktual dan kondisi yang dituju, beserta hambatan dan strategi untuk menanganinya |

## Interpretation Rules

1. Functional Object menjelaskan **objek functioning**, bukan perilaku tertentu.
2. Functional Object bukan daftar indikator.
3. Functional Object bukan nama lain dari Functional Dimension.
4. Functional Object tidak menentukan tahapan perkembangan.
5. Functional Object tidak menentukan instrumen atau metode assessment.
6. Functional Object tidak menentukan program atau intervensi tertentu.
7. Functional Object tidak boleh memasukkan klaim keberhasilan atau efektivitas yang belum didukung evidence.

## Boundary terhadap Functional Dimension

Perbedaannya harus dipertahankan:

> **Functional Object = apa yang menjadi objek functioning.**
>
> **Functional Dimension = fungsi penting apa yang dibedakan di dalam objek tersebut.**

Contoh pada Problem Solving:

```text
Problem Solving
      ↓
Gap / problem situation and its handling
      ↓
Problem Representation
Strategy Generation / Selection
Action Adjustment
```

Object tidak boleh dipersempit menjadi salah satu dimension, dan dimension tidak boleh menggantikan object.

## Boundary terhadap Evidence

Functional Object bukan evidence.

Evidence adalah informasi yang digunakan untuk mendukung inference tentang functioning atau construct. Satu task atau satu observasi tidak otomatis mewakili seluruh Functional Object maupun seluruh Core Capacity.

## Cross-Context Rule

Functional Object harus cukup stabil untuk mempertahankan identitas construct lintas konteks, tetapi manifestasi dari object tersebut dapat berbeda menurut:

- konteks;
- demand;
- relasi;
- bahasa dan budaya;
- resources;
- support;
- tools;
- dan kondisi lingkungan.

Karena itu, perbedaan manifestasi lintas konteks tidak otomatis berarti perubahan identitas Functional Object.

## Non-Equivalence Rules

- Functional Object ≠ Core Capacity.
- Functional Object ≠ Functional Dimension.
- Functional Object ≠ sub-capacity.
- Functional Object ≠ behavior.
- Functional Object ≠ task.
- Functional Object ≠ indicator.
- Functional Object ≠ assessment item.
- Functional Object ≠ performance.
- Functional Object ≠ normative construct.
- Functional Object ≠ intervention target yang sudah dipastikan efektif.

## Governance

Perubahan Functional Object harus diuji terhadap:

- definisi canonical Core Capacity;
- construct identity;
- Functional Dimensions;
- boundaries;
- capacity relationships;
- evidence territory;
- dan traceability.

Jika perubahan memperluas, mempersempit, atau mengubah ruang lingkup construct secara material, perubahan tersebut harus diperlakukan sebagai **construct revision**, bukan sekadar edit terminologi.

Perubahan juga harus meninggalkan jejak pada governance yang relevan, termasuk Construct Registry dan Claim Registry bila perubahan menghasilkan klaim baru.

## Validation Status

Arsitektur ini berstatus **conceptually specified / empirically provisional**.

Pemetaan Functional Object di atas adalah keputusan arsitektural saat ini; ia belum merupakan bukti empiris bahwa setiap object telah tervalidasi universal atau lintas budaya.
